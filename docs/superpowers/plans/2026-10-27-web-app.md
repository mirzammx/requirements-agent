# Local Web App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]` checkboxes.

**Goal:** Browser buttons for shortlist → decision → triage → card → response → download.
**Spec:** `docs/superpowers/specs/2026-10-27-web-app-design.md`
**Tech Stack:** Flask (Jinja2), threading; existing pipeline; Docker Compose service `web`.

## Global Constraints
- Run tests in Docker. Bind the server to 127.0.0.1:8000 on the host.
- The web layer calls only `run_triage`, `run_draft` and `run_shortlist`.
- In tests, jobs run synchronously (`app.config["SYNC_JOBS"] = True`).

## Review Focus
1. Path traversal in downloads (`test_download_rejects_traversal`).
2. A job that fails → the error is shown and the page stops refreshing (`test_failed_job_shows_error`).
3. Pressing "Generate response" twice while a job runs → only one job (`test_double_submit_starts_one_job`).
4. A decision for an unknown tender id → 400 (`test_decide_unknown_tender_400`).
5. Upload with no files → form error, no empty bid (`test_upload_without_files_errors`).

### Task 1: Pipeline functions
- `triage.run_triage(path, *, provider, model=None, effort="high", out_base=Path("out"), out_dir=None) -> Path`
- `draft.run_draft(path, card_dir, *, provider, model=None, effort=None, from_draft=None) -> dict[str, int | None]` (also writes `response/summary.json`)
- `shortlist.run_shortlist(paths, *, provider, model=None, effort="low", out_base=Path("out"), out_dir=None) -> Path`
- `main()` functions become thin wrappers; existing CLI tests stay green. Commit.
